Додаток А: Опис підсумкового проєкту Підсумковий проєкт (ІНДЗ): Розробка програмного рішення на базі Google Gemini API для вирішення освітньо-технічної задачі 1. Мета проєкту Продемонструвати глибокі навички промпт-інженерії та програмної інтеграції великих мовних моделей (LLM) для створення функціонального прототипу, що вирішує конкретну освітньо-технічну проблему. Студенти мають застосувати знання з архітектури ШІ-систем, роботи з API та розробки програмного забезпечення для реалізації комплексного рішення. 2. Основні компоненти проєкту 2.1. Визначення освітньо-технічної задачі: • Чітко сформулюйте проблему, яку ви прагнете вирішити. Акцент має бути на автоматизації, аналізі або створенні інструментів для студентів-програмістів, викладачів технічних дисциплін або адміністраторів освітніх IT-систем. • Опишіть цільову аудиторію та її технічний контекст. • Поясніть актуальність та технічну значущість обраної задачі. 2.2. Проєктування та розробка рішення: • Вибір моделі: Обґрунтуйте вибір конкретної моделі з лінійки Google Gemini (напр., Gemini Pro для складних завдань або Gemini Flash для завдань, що потребують низької затримки). Робота ведеться через  Google AI Studio для прототипування та отримання API-ключів. • Архітектура рішення: Опишіть загальну архітектуру вашого проєкту. Наведіть схему взаємодії компонентів. • Промпт-інженерія (ключовий компонент): o Розробіть детальні системні та користувацькі промпти, що є ядром вашого рішення. o Продемонструйте використання просунутих технік (Chain-of-Thought, Few-Shot для JSON, симуляція Tree-of-Thought). o Покажіть процес ітеративного вдосконалення промптів: наведіть приклади початкових версій, проблем та фінальних версій, що вирішують ці проблеми. • Технічна інтеграція (обов'язковий компонент): o Продемонструйте програмну взаємодію з Gemini API, використовуючи  Python та бібліотеку google-generativeai або Google Apps Script. o Залежно від проєкту, реалізуйте один з двох підходів:  RAG (Retrieval-Augmented Generation) або Agents (з Function Calling). 2.3. Реалізація та тестування: • Продемонструйте роботу вашого програмного рішення (відео-скрінкаст або жива демонстрація). • Наведіть приклади API-запитів та отриманих відповідей. • Опишіть процес тестування: як ви перевіряли коректність роботи логіки, обробку помилок та надійність інтеграції. • З якими технічними обмеженнями чи недоліками моделі ви зіткнулися? 2.4. Аналіз етичних аспектів: • Проаналізуйте потенційні етичні та безпекові проблеми, специфічні для вашого кейсу (ризик prompt injection, конфіденційність даних при роботі з API, авторське право на згенерований код, упередженість). • Запропонуйте конкретні технічні або процедурні рішення для мінімізації цих ризиків у вашому проєкті. 2.5. Висновки та подальший розвиток: • Підсумуйте результати, наголошуючи на технічних досягненнях та інноваційності рішення. • Оцініть потенціал масштабування вашого прототипу. • Запропонуйте можливі шляхи для подальшого вдосконалення. 3. Вимоги до оформлення та подачі 1. Письмовий звіт (Google Docs або PDF): Документ, що детально описує всі 5 компонентів проєкту. Має містити титульну сторінку, зміст, усі розділи, схеми архітектури та додатки з ключовими фрагментами коду та текстами промптів. 2. Презентація та демонстрація (5-10 хвилин): Коротка технічна презентація, що демонструє архітектуру, ключові промпти, живу роботу програмного рішення та основні висновки. 3. Репозиторій коду (обов'язково): Посилання на репозиторій (напр., GitHub) з усім кодом проєкту, що містить README.md файл з інструкціями по запуску. 4. Критерії оцінювання (40 балів) Оцінка за підсумковий проєкт складається з таких компонентів: • Актуальність та постановка задачі (6 балів): Оцінюється чіткість визначення освітньо-технічної проблеми та її значущість. • Глибина та ефективність промпт-інженерії (14 балів): Оцінюється якість та складність розроблених системних промптів, використання релевантних технік, демонстрація ітеративного процесу покращення. • Технічна реалізація та інтеграція (8 балів): Оцінюється якість, чистота та функціональність коду; коректність роботи з API; складність реалізованої архітектури (RAG/Agents). • Аналіз етичних аспектів (6 балів): Оцінюється глибина аналізу технічних ризиків та обґрунтованість запропонованих рішень. • Якість звіту та презентації (6 балів): Оцінюється структурованість, повнота, ясність викладу у звіті та якість демонстрації проєкту. 5. Варіанти завдань для підсумкового проєкту (Приклади) • Категорія 1: Інструменти для розробників та студентів-програмістів 1. Чат-бот для роботи з документацією: Створити чат-бота, який використовує RAG для відповідей на питання по документації конкретної бібліотеки або фреймворку (напр., TensorFlow, React). 2. Інструмент для рефакторингу та пояснення коду: Розробити вебдодаток, куди користувач може вставити фрагмент коду, а система на основі Gemini Pro генерує його покрокове пояснення (використовуючи CoT) та пропонує варіанти для рефакторингу. 3. Генератор Unit-тестів: Створити інструмент, який приймає на вхід функцію або клас на Python і генерує для нього набір Unit-тестів з використанням бібліотеки unittest або pytest. • Категорія 2: Автоматизація освітніх процесів  4. Автоматизований асистент для перевірки коду. Розробити систему на базі Google Apps Script, яка автоматично аналізує програмні завдання студентів, здані у Google Classroom. Скрипт за допомогою Gemini API перевіряє код на відповідність стилю (PEP8) та наявність коментарів, після чого залишає автоматичний коментар-фідбек.  5. Інтелектуальний планувальник навчального плану. Створити інструмент, який на основі списку тем та бажаних результатів навчання генерує деталізований навчальний план (syllabus) для технічного курсу, включаючи ідеї для практичних завдань та список рекомендованої літератури.
